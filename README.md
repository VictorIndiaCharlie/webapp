# Anagram Generator — Tier-3 Webapp on AWS

A full-stack anagram discovery tool that turns names (with or without spaces, with or without diacritics) into exact anagrams, sub-anagrams, and multi-word phrases — including pronounceable **invented words** generated by a Markov chain.

**Live URL:** `http://<your-alb-dns>.eu-central-1.elb.amazonaws.com`

## What It Does

### Features

- **Exact anagrams** — all dictionary words using exactly the same letters
- **Sub-anagrams** — smaller words formed from a subset of the input letters
- **Multi-word phrases** — 2-word (and optionally 3-word) combinations that use the full letter pool
- **Invented words** — a Markov chain trained on the real dictionary generates ~11K pronounceable pseudo-words (`amari`, `miara`, `arima`), giving more options for any search
- **Space-sensitive input** — `maria elena` is treated as a 10-letter pool, not two separate searches
- **Diacritic normalization** — `Ștefan`, `Ștefán`, `stefan` all resolve to `stefan`
- **Live counter** — each search shows how many results were found in that specific search (resets between queries)
- **Dictionary viewer** — see every name currently stored in the database
- **Random name button** — one-click "surprise me" pull from the seeded names

### Sample Search

Input: `maria`

```json
{
  "input": "maria",
  "exact": [
    {"word": "amari", "invented": true},
    {"word": "arima", "invented": true},
    {"word": "maria", "invented": false}
  ],
  "sub_anagrams": [
    {"word": "aim", "invented": false},
    {"word": "air", "invented": false},
    {"word": "arm", "invented": false}
  ],
  "phrases": [["aim", "ram"], ["air", "am"]],
  "stats": {
    "exact_count": 3,
    "sub_count": 47,
    "phrase_count": 12,
    "total": 62,
    "time_ms": 45.2
  }
}
```

The **`invented: true`** flag drives a dashed-border style in the UI so users can distinguish real words from synthetic ones.

### Design Choices

| Choice | Why |
|---|---|
| **Three separate EC2s** (not one big box) | Demonstrates real tier separation; each service can be scaled independently |
| **Nginx inside the frontend EC2** | Handles the `/api/*` proxy hop, allowing the browser to see a single origin |
| **S3 artifact bucket** | Removes need for GitHub tokens on EC2 (works with private repos, zero secrets on disk) |
| **SSM Session Manager** (not SSH) | No SSH keys to manage, no open port 22, all access is IAM-audited |
| **IAM role for S3 read** | Least privilege — one bucket, one object prefix, `GetObject` only |
| **Markov inventor runs at startup** | Pseudo-words are generated once (~250ms) and cached in memory → zero query-time cost |

## Local Development

Everything runs in Docker Compose on a single machine — no Terraform needed.

```bash
# 1. Build + start all containers
docker compose up --build -d

# 2. Wait ~10 seconds for DB init and backend startup
docker compose ps      # all should say "Up"

# 3. Open the app
# → http://localhost:8080 (nginx)

# 4. Tear down
docker compose down -v
```

### Structure notes

| Container | Port (host) | Port (internal) | Purpose |
|---|---|---|---|
| `db` | 5432 | 5432 | PostgreSQL with seeded names |
| `backend` | 8000 | 8000 | FastAPI |
| `frontend` | — | 3000 | Node.js serving SPA |
| `nginx` | 8080 | 80 | Public entry, proxies `/` and `/api` |

The `db` and `backend` ports are published so you can hit them directly during debugging (e.g., `psql -h localhost -p 5432 -U anagram`).

## AWS Deployment (Terraform)

### Prerequisites

```bash
# Tools
terraform >= 1.7
awscli >= 2.x
session-manager-plugin    # for SSM access
jq                        # optional, for parsing JSON output
docker                    # for building the artifact tarball

# AWS credentials configured
aws configure
aws sts get-caller-identity
```

### First-Time Deploy

```bash
# 1. Build the app tarball
cd ~/webapp/anagram-generator
./build.sh

# 2. Initialize Terraform (first time only)
cd terraform
terraform init

# 3. Review the plan
terraform plan

# 4. Apply (~10 minutes end-to-end)
terraform apply -auto-approve

# 5. Wait ~10 minutes for user_data scripts to finish.
#    Then check:
URL="http://$(terraform output -raw alb_dns_name | sed 's|http://||')"
curl -s -o /dev/null -w "/    -> %{http_code}\n" "$URL/"
curl -s -o /dev/null -w "/api -> %{http_code}\n" "$URL/api/words/random"
```

**Both curls should return `200`.** If one returns `502` or `503`, see the [Debugging Checklist](#debugging-checklist).

### Redeploying Code Changes

The workflow after any change to `frontend/`, `backend/`, `db/`, `nginx/`, or `docker-compose.yml`:

```bash
# 1. Rebuild the tarball
cd ~/webapp/anagram-generator
./build.sh

# 2. Force-replace the affected EC2s
cd terraform
terraform apply -auto-approve \
  -replace=module.ec2.aws_instance.backend \
  -replace=module.ec2.aws_instance.frontend

# 3. Wait ~6 minutes, then test
```

The tarball is uploaded to S3 as part of the `aws_s3_object` resource, and the new EC2s pick it up on boot.

**⚠️ Critical:** `./build.sh` must run **before** `terraform apply`. Terraform reads `/tmp/anagram-app.tar.gz` at plan time. If it's missing, plan fails.

### Accessing Instances

**Never SSH.** All access goes through AWS Systems Manager:

```bash
# Get an instance ID
FRONTEND=$(aws ec2 describe-instances \
  --filters "Name=tag:Name,Values=anagram-frontend" "Name=instance-state-name,Values=running" \
  --query "Reservations[0].Instances[0].InstanceId" --output text)

# Open an interactive shell
aws ssm start-session --target "$FRONTEND" --region eu-central-1

# Or run commands without a shell
aws ssm send-command --instance-ids "$FRONTEND" \
  --document-name "AWS-RunShellScript" \
  --parameters 'commands=["docker ps","sudo tail -20 /var/log/user-data.log"]' \
  --region eu-central-1 --query "Command.CommandId" --output text
```

### Destroy Everything

```bash
cd terraform
terraform destroy -auto-approve
```

This removes the S3 bucket (`force_destroy = true`), all EC2s, the VPC, and the ALB. The Terraform state stays in S3 (see below), so a fresh `apply` reproduces everything.

### State Management

Terraform state lives in **S3** with versioning + encryption enabled:

```text
s3://anagram-tfstate-<account-id>/anagram-app/terraform.tfstate
```

This protects against the "empty state file" bug — S3 versioning means you can always roll back to the previous state if something corrupts the current one.

Backup commands:

```bash
# List state versions
aws s3api list-object-versions \
  --bucket anagram-tfstate-412654396693 \
  --prefix anagram-app/terraform.tfstate \
  --query "Versions[].[VersionId, LastModified]"

# Restore a specific version
aws s3api copy-object \
  --bucket anagram-tfstate-412654396693 \
  --copy-source "anagram-tfstate-412654396693/anagram-app/terraform.tfstate?versionId=<vid>" \
  --key anagram-app/terraform.tfstate
```

## How the Anagram Engine Works

The backend uses three complementary data structures, all built once at startup and cached in memory.

### 1. Exact anagrams — O(1) hashmap lookup

Every word is stored with a "signature key" = its letters, lowercased, sorted:

| Word | Signature key |
|---|---|
| `maria` | `aaimr` |
| `amari` | `aaimr` |
| `miara` | `aaimr` |

Searching `maria` → compute `aaimr` → look up in `EXACT_MAP["aaimr"]` → return all matches. **O(1) regardless of dictionary size.**

### 2. Sub-anagrams — 26-integer subset check

For each dictionary word, we precompute a 26-int tuple of letter counts `(count_a, count_b, ..., count_z)`. A word is a sub-anagram if:

```python
all(word_counts[i] <= input_counts[i] for i in range(26))
```

This is **26 integer comparisons** instead of string manipulation. For 11K words it runs in ~2ms.

### 3. Phrases — hashmap lookup on the remainder

Instead of the naive `O(D²)` nested loop over all word pairs, we:

1. Iterate subset keys (not all words)
2. Subtract the first word's letter counts from the input
3. Look up the remainder in `EXACT_MAP` — **one hashmap lookup per candidate**

This turns phrase-finding from `O(D²)` into `O(S)` where `S` ≈ number of sub-anagrams (typically <500).

### 4. Invented words — Markov chain, generated once

`inventor.py` trains a bigram model on the real dictionary at startup:

- Boundary marker `^` before each word, `$` after
- `P(next_char | prev_char)` learned from ~880 real words
- `generate(length=N)` samples a walk from `^` to `$` of length N

~11K pseudo-words generated in ~250ms at boot and added to `INVENTED_MAP`. Query-time cost: **zero** — they're just extra buckets in the same hashmap.

### 5. Caching — `@lru_cache(maxsize=4000)`

Every unique `(input_key, max_words, invented)` combination is memoized:

| Query | First hit | Cache hit |
|---|---|---|
| `maria` | ~45ms | ~0.1ms |
| `maria elena` | ~180ms | ~0.3ms |
| `alexandru` | ~140ms | ~0.2ms |

Cache invalidates automatically when a user adds a new word.

## Debugging Checklist

### Symptom: `/ → 502`

The frontend EC2 can't be reached by the ALB. **Most likely cause:** nginx isn't up yet (still building), or the target is deregistered.

```bash
# 1. Check target health
TG_ARN=$(aws elbv2 describe-target-groups --names anagram-frontend-tg \
  --query "TargetGroups[0].TargetGroupArn" --output text)
aws elbv2 describe-target-health --target-group-arn "$TG_ARN" \
  --query "TargetHealthDescriptions[].{State:TargetHealth.State,Reason:TargetHealth.Reason}" \
  --output table

# 2. Check frontend containers
FRONTEND=$(aws ec2 describe-instances \
  --filters "Name=tag:Name,Values=anagram-frontend" "Name=instance-state-name,Values=running" \
  --query "Reservations[0].Instances[0].InstanceId" --output text)

aws ssm send-command --instance-ids "$FRONTEND" \
  --document-name "AWS-RunShellScript" \
  --parameters 'commands=["docker ps -a","sudo tail -40 /var/log/user-data.log"]' \
  --region eu-central-1 --query "Command.CommandId" --output text > /tmp/fe.txt
sleep 10
aws ssm get-command-invocation --command-id "$(cat /tmp/fe.txt)" --instance-id "$FRONTEND" \
  --region eu-central-1 --query "StandardOutputContent" --output text
```

### Symptom: `/ → 200, /api → 502`

Frontend is up. Backend isn't reachable. **Three causes:**

1. **Backend container down** — check `docker ps` on backend EC2
2. **Backend ports not published** — `docker port anagram_backend` should show `0.0.0.0:8000->8000/tcp`
3. **nginx stale IP** — compare `grep backend_upstream /home/ec2-user/app/nginx/nginx.conf` against the backend's actual private IP

### Symptom: `/api → 500`

Backend is up but can't reach the DB. **Almost always a password mismatch.**

```bash
# Get DB's actual password
DB=$(aws ec2 describe-instances \
  --filters "Name=tag:Name,Values=anagram-db" "Name=instance-state-name,Values=running" \
  --query "Reservations[0].Instances[0].InstanceId" --output text)

aws ssm send-command --instance-ids "$DB" \
  --document-name "AWS-RunShellScript" \
  --parameters 'commands=["docker exec anagram_db printenv POSTGRES_PASSWORD"]' \
  --region eu-central-1 --query "Command.CommandId" --output text > /tmp/dbpw.txt
sleep 8
aws ssm get-command-invocation --command-id "$(cat /tmp/dbpw.txt)" --instance-id "$DB" \
  --region eu-central-1 --query "StandardOutputContent" --output text
```

Then set the backend to match (see [Lessons Learned](#lessons-learned--the-bugs-we-fixed) below).

### Symptom: Browser says "site can't be reached" but curl works

**Cause:** Brave/Chrome/Safari auto-upgrade `http://` to `https://`. Your ALB only has HTTP on port 80.

**Fix:** Type `http://` explicitly in the address bar:

```text
http://anagram-alb-xxxx.eu-central-1.elb.amazonaws.com
```

Or disable HTTPS-Only Mode in Brave: `brave://settings/security`.

### Universal Rule: Always `--no-cli-pager`

AWS CLI pipes long output to `less`. If you see a `:` prompt, that's not a hang — press `q`. To prevent it:

```bash
export AWS_PAGER=""
```

Or add `--no-cli-pager` to each command.

## Lessons Learned

Every one of these actually happened during this project. They're documented so future-you (or a teammate) doesn't repeat the debugging loop.

### 1. `requirements.txt` not found at `COPY` step

**Error:** `failed to compute cache key: "/requirements.txt": not found`
**Cause:** File was in wrong folder, or named `Requirements.txt` (capital R — Linux is case-sensitive).
**Fix:** Verify with `ls -la backend/`. Rebuild with `docker builder prune -f && docker compose build --no-cache`.

### 2. `init.sql` was a directory, not a file

**Error:** `psql: error: could not read from input file: Is a directory`
**Cause:** Accidentally created `db/init.sql` as a directory.
**Fix:** `rm -rf db/init.sql && cat << 'EOF' > db/init.sql ...`

### 3. Nginx showed "Welcome to nginx!" instead of the app

**Cause:** `default.conf` wasn't deleted from the nginx image before copying ours in.
**Fix:** In `nginx/Dockerfile`, add `RUN rm /etc/nginx/conf.d/default.conf` before `COPY`.

### 4. Nginx restart loop: `unknown directive "nginx/nginx.conf"`

**Cause:** A `cat > nginx/nginx.conf` command was pasted incorrectly, writing the filename into the file itself.
**Fix:** Overwrite the file cleanly with `cat << 'EOF' > nginx/nginx.conf`.

### 5. `docker compose build requires buildx 0.17.0 or later`

**Cause:** Docker Compose v5+ requires the `buildx` plugin for `docker compose build`. Alpine's `docker` package doesn't include it.
**Fix:** Add to every `user_data` template:

```bash
curl -SL "https://github.com/docker/buildx/releases/download/v0.17.1/buildx-v0.17.1.linux-amd64" \
  -o /usr/local/lib/docker/cli-plugins/docker-buildx
chmod +x /usr/local/lib/docker/cli-plugins/docker-buildx
```

### 6. `docker compose up` stalls for 5 minutes then fails silently

**Cause:** `docker compose up frontend nginx` starts the **entire dependency chain** (frontend → backend → db). On a fresh EC2, the db container's health check waits 50 seconds before timing out, so `set -e` kills the script before any container starts.
**Fix:** Use `--no-deps` in every user_data:

```bash
docker compose up -d --no-deps frontend nginx   # frontend EC2
docker compose up -d --no-deps backend          # backend EC2
docker compose up -d --no-deps db               # db EC2
```

### 7. Backend on EC2: `NOTHING_ON_8000`, DB: `DB_NOT_LISTENING`

**Cause:** `docker-compose.yml` was written for local dev where services talk via Docker's bridge network (`db:5432`, `backend:8000`). On **separate EC2s**, they must go through the host IP, which requires port publishing.
**Fix:** Add `ports:` blocks:

```yaml
backend:
  ...
  ports:
    - "8000:8000"
db:
  ...
  ports:
    - "5432:5432"
```

**Note:** These ports are only reachable from inside the VPC — the security groups block external access. The DB SG only allows port 5432 **from the backend SG**, and the backend SG only allows 8000 from the frontend SG.

### 8. Backend 503: `password authentication failed for user "anagram"`

**Cause:** The `user_data` template's `sed` was too strict:

```bash
# Only matched "POSTGRES_PASSWORD: anagram"
sed -i "s|POSTGRES_PASSWORD: anagram|POSTGRES_PASSWORD: ${postgres_password}|g"
```

If the compose file had `${POSTGRES_PASSWORD:-anagram}` (env-var expression), the `sed` missed, so the backend and DB got different effective passwords.
**Fix:** Match anything:

```bash
sed -i "s|POSTGRES_PASSWORD: .*|POSTGRES_PASSWORD: ${postgres_password}|g"
```

Same fix applied to `POSTGRES_HOST` — use `.*` so it works whether the file contains `db` or an old hardcoded IP.

### 9. Terraform state file became 182 bytes (empty)

**Cause:** A `terraform` command was interrupted mid-write (Ctrl+C during apply, or a race with `terraform init -migrate-state`). The writer truncates first, then writes — Ctrl+C in that window leaves a 0-byte file.
**Fix:**
1. Restore from `terraform.tfstate.backup` (always present after any apply)
2. Migrate to S3 backend permanently:

```hcl
terraform {
  backend "s3" {
    bucket       = "anagram-tfstate-<account-id>"
    key          = "anagram-app/terraform.tfstate"
    region       = "eu-central-1"
    encrypt      = true
    use_lockfile = true
  }
}
```

With S3 versioning enabled, you can always roll back to a previous state version.

### 10. Browser "site can't be reached" but curl works

**Cause:** Brave (and Chrome, Safari, Firefox) auto-upgrade `http://` to `https://`. The ALB only has an HTTP listener on port 80 → HTTPS connection refused.

**Fix:** Type `http://` explicitly. Or disable in Brave: `brave://settings/security` → "Always use secure connections" → OFF.

**Permanent fix:** Add an ACM certificate and an HTTPS listener to the ALB (see [Roadmap](#roadmap)).

### 11. `jq: command not found`

**Fix:** Either `sudo apt install -y jq`, or use `aws ... --query` with built-in JMESPath instead of piping to jq.

### 12. `aws` CLI hangs on `:` prompt

**Cause:** Long output is piped to `less`. The `:` at the bottom is the pager prompt, not a hang.
**Fix:** Press `q`. Prevent recurrence with `export AWS_PAGER=""`.

### 13. `sudo -i` showed `root@Belobog` (local machine, not EC2)

**Cause:** Ran `sudo -i` while still in a local shell. The `aws ssm start-session` command had exited silently (missing session-manager-plugin at the time).
**Fix:** Install `session-manager-plugin`, then re-run `aws ssm start-session`. Confirm you're on the EC2 by checking the prompt — it should be `sh-5.2$`, not `root@Belobog`.

### 14. `resource "aws_s3_object" ...` gave "Command not found"

**Cause:** Pasted HCL into bash.
**Fix:** HCL belongs in `.tf` files. Use shell commands like `ls /tmp/anagram-app.tar.gz` to verify what the HCL reads.
